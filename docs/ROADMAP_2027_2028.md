# CodeContext 2027–2028 Roadmap

This roadmap is organized around engineering problems that become more important as AI-generated code volume increases.

## Now — Evidence Foundation

- Grounded repository Q&A
- Deterministic engineering planning
- Versioned evidence contracts
- Stable CLI and CI artifacts
- Full Linux/Windows verification

## Next — Verification and Governance

1. SARIF output and native CI annotations
2. Architecture Constitution / policy-as-code
3. Architecture drift snapshots and temporal comparison
4. Ownership and knowledge concentration graph
5. Explainable risk budgets
6. Change Proof artifacts
7. Security and dependency evidence integration

## Then — Simulation and Migration Safety

8. Counterfactual impact simulation
9. API/schema compatibility analysis
10. Migration Guardian
11. Test adequacy and change-to-test traceability
12. Historical regression intelligence

## AI-native engineering

13. AI Change Provenance
14. Evidence-validated AI review
15. AI-assisted implementation planning
16. Isolated patch generation
17. CI-validated repair loops
18. Agent Firewall / policy enforcement

## Organization scale

19. Cross-repository dependency graph
20. Organization architecture map
21. Knowledge continuity graph
22. Engineering health trends
23. Governance dashboards
24. Runtime-to-code incident correlation

## Platform principles

- local-first remains supported;
- every important result is machine-readable;
- deterministic evidence remains authoritative;
- uncertainty is explicit;
- AI output is validated against evidence;
- autonomous changes require isolation and CI verification;
- organization features are optional extensions, not requirements for the CLI.

## What success looks like

CodeContext should become the system that answers:

> **What changed, what can it affect, why do we believe that, what policy does it touch, what must be verified, and can we prove the resulting change is safe for this exact repository state?**
